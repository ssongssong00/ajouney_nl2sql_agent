# Ajouney+ NL2SQL 에이전트

OTT 서비스 'AJOU사'의 고객 여정 대시보드 위에서, 마케터가 업무 용어로 질문하면 SQL을 만들어 답하는 에이전트입니다. 정의는 시맨틱 레이어에서 찾아 쓰고, 실행 전에는 하네스가 SQL을 검증합니다. 답변에는 숫자와 함께 계산 기준, 실행한 SQL, 검증 과정을 같이 보여 줍니다.

> 2026 해커톤 6팀 · 문제 1(고객 여정 대시보드) + 문제 2(시맨틱 레이어 기반 NL2SQL 에이전트)

![대시보드와 AI 에이전트 패널](docs/images/overview.png)

- **대시보드 + 챗봇:** 대시보드가 화면 전체를 쓰고, 오른쪽 "AI 에이전트" 패널에서 질문합니다. 같은 패널의 "하네스 모니터링" 탭에서 모든 실행 기록을 봅니다.
- **서버 없음:** 고객 데이터를 브라우저 안의 SQLite(sql.js)에 올려 조회합니다. claude.ai 아티팩트로 배포합니다.
- **대시보드와 같은 숫자:** D+30 결제 전환율 24.9%, D+22~28 유지율 48.9%, 4주 지속 시청 고객 4,009명 등 대시보드·발표 자료의 숫자를 그대로 재현합니다(자동 테스트로 고정).

## 주요 화면과 기능

### 1. 대시보드 · 고객 여정 현황

상단 필터(가입일 범위, 가입 기기, 연령대, 푸시 수신)를 바꾸면 모든 지표가 다시 계산되고, 오른쪽 위에 선택된 고객 수가 표시됩니다. 각 지표의 ⓘ에는 분자·분모 정의가 들어 있습니다.

**퍼널 KPI 요약:** 고객 여정을 4단계 카드로 요약합니다.

![퍼널 KPI 요약](docs/images/dashboard-kpi.png)

| 단계 | 보여 주는 지표 |
|---|---|
| 1. 가입 · 탐색 | 전체 가입 고객 50,000명, 탐색률 60.2% |
| 2. 이용권 관심 · 첫 결제 | 이용권 페이지 방문 57.3%, 첫 결제 전환율 D+7 · D+14 · D+30 (24.0% · 24.4% · 24.9%) |
| 3. 초기 시청 | 결제 후 시청 활성화율 D+7 · D+14 · D+28 (79.4% · 82.8% · 85.6%), 결제 후 7일 미시청 20.6% |
| 4. 지속 시청 | D+22~28 시청 유지율 48.9%, VOD · 영화 · LIVE 이용률 |

**가입 주차별 코호트 추이:** 가입일을 7일 단위 코호트로 묶어 D+30 결제, 탐색, 초기 시청, 4주차 시청 비율이 가입 시기별로 어떻게 달라지는지 봅니다. 점선은 필터 전체 평균입니다.

![가입 주차별 코호트 추이](docs/images/dashboard-cohort.png)

**퍼널 병목 구간:** 앞 단계를 모두 거친 고객만 세는 순차 퍼널입니다(가입 → 탐색 → 이용권 관심 → 첫 결제 → 초기 시청 → 지속 시청). 직전 단계 대비 전환율이 가장 낮은 구간을 "병목"으로 표시합니다. 오른쪽에는 병목 고객군별 인원, 푸시 도달 수, 추출 조건이 나오고, 대상 고객 명단을 복사할 수 있습니다.

![퍼널 병목 구간](docs/images/dashboard-funnel.png)

**타깃 고객군 우선순위:** 전환 가능성과 실행 가능성으로 정한 1~3위 타깃입니다. 카드를 고르면 선정 근거와 추출 조건, 명단 복사 버튼이 나옵니다.
1. 이용권 관심 후 미결제 (즉각 매출 창출)
2. 선택 피로 방랑 유저 (시청 활성화)
3. 가입 후 미탐색 (서비스 탐색 유도)

![타깃 고객군 우선순위](docs/images/dashboard-targets.png)

**세그먼트 비교:** 가입 기기·연령대 등 세그먼트별 전환율을 평균선과 함께 비교하고, 평균보다 낮은 세그먼트 중 최저를 빨간색으로 표시합니다. 50명 미만 세그먼트는 숨깁니다.

![세그먼트 비교](docs/images/dashboard-segments.png)

**콘텐츠:** 결제 후 첫 주에 처음 본 콘텐츠 기준 4주차 시청 유지율 상위 작품과, 장르별 유지율 상·하위를 보여 줍니다. 표본이 작은 작품(50명 미만)과 장르(100명 미만)는 제외합니다.

### 2. 대시보드 · 핵심 타깃 · 콘텐츠 선택

2순위 타깃인 **선택 피로 방랑 유저**(D0~D30 검색 3회 이상, 재생 클릭 0회)를 깊게 봅니다. 추천 콘텐츠를 누른 고객은 50,000명 중 72명뿐이라, 고르지 못하는 고객에게 추천이 닿지 않는다는 문제 제기로 시작합니다.

![핵심 타깃 탭](docs/images/target-overview.png)

**타깃 규모:** 방랑 유저 10,216명, 그중 푸시 수신 가능 4,270명, 결제 고객 4,961명입니다. 검색 횟수 기준(3회+ · 5회+ · 10회+)을 바꾸면 이 탭과 고객 여정 탭의 관련 지표가 모두 다시 계산됩니다.

![선택 피로 방랑 유저 규모](docs/images/target-kpi.png)

**행동 분석:** 검색 횟수가 늘수록 재생 전환이 오르는 흐름과, 방랑 유저가 같은 검색량의 재생 고객보다 찜·재생 클릭이 거의 없다는 점을 비교합니다.

![검색 횟수별 재생 전환과 행동 비교](docs/images/target-behavior.png)

**타깃 프로필 · 실행:** 방랑 유저의 기기·연령 구성비를 전체 고객과 비교합니다. 실행 쪽에는 추출 조건, 명단·푸시 대상 복사, 추천 액션, 성과 KPI를 정리했습니다.

1. **핵심 답변:** 요약 문장과 핵심 숫자. 답변 위 태그로 "Claude 생성"인지 "템플릿 모드"인지 표시합니다.
2. **분석 결과:** 비교는 막대, 추이는 선 차트로 그리고, 결과 표와 해석 시 주의점·다음 행동 제안을 함께 보여 줍니다.
3. **적용된 분석 기준:** 지표, 계산식, 분자·분모, 기간, 차원, 필터, 가정, 사용한 시맨틱 정의 id
4. **SQL · 하네스 검증:** 실행한 SQL과 단계 타임라인, 검증 항목 13개의 결과. 자동 수정이 있었다면 수정 전후 SQL 비교도 함께 나옵니다.
5. **검색된 정의 (RAG Context):** 선택된 정의, 검색 순위·점수, LLM에 넘긴 Context 원문

같은 질문을 다시 하면 이전 실행과 정의 버전·검색 결과·SQL·결과가 달라졌는지 비교해 줍니다. 패널 아래의 "Claude 연결 확인"으로 Claude 호출이 어느 단계에서 실패하는지 점검할 수 있습니다.

### 4. AI 에이전트 · 하네스 모니터링

모든 실행 기록을 상태별로 모아 봅니다. 공유 로그 DB에 연결돼 있으면 최근 300건을 불러옵니다.

![하네스 모니터링](docs/images/monitor-tests.png)

- **상태 카드:** 검증 성공 · 검증 실패 · 자동 수정 성공 · 재시도 실패 · 위험 SQL 차단. 카드를 누르면 그 상태만 걸러 봅니다.
- **테스트 실행:** 하네스 시나리오 6개(정상 질문, 없는 컬럼 수정, 삭제 SQL 차단, 문법 오류 수정, 데이터 없는 지표, 업무 용어 질문)를 돌려 기대값·실제값·통과 여부를 표로 보여 줍니다.
- **실행 이력:** 시각, Request ID, 질문, 상태, 재시도 횟수, 오류 유형
- **내려받기:** 로그 전체와 테스트 결과를 JSON 파일로 저장합니다(claude.ai 아티팩트에서만).

행을 누르면 그 실행의 상세가 나옵니다.

<img src="docs/images/monitor-detail.png" alt="실행 상세: Context, 단계 타임라인, SQL 비교, 오류 피드백" width="560">

1. 질문과 검색된 Context(정의·테이블·필터·JOIN)
2. 단계 타임라인
3. 최초 SQL과 수정 SQL의 줄 단위 비교
4. 오류 유형, 수정기에 넘긴 오류 피드백, 수정 이유와 엔진(LLM/규칙), 최종 결과

## 왜 이렇게 만들었나

마케터가 "20대 고객의 초기 미시청률은?"을 물을 때 필요한 것은 SQL 실력이 아니라 **팀이 합의한 지표 정의**입니다. 그리고 LLM이 만든 SQL을 그대로 실행하면 정의가 조금씩 달라지거나, 없는 컬럼을 쓰거나, 데이터를 바꾸는 SQL이 섞일 수 있습니다. 그래서 다음 두 가지를 축으로 삼았습니다.

1. **정의는 시맨틱 레이어에서:** 지표의 계산식, 분자·분모, 기간, 필터를 한곳(`data/`)에 정의하고, 질문과 관련된 정의만 검색해 LLM에 넘깁니다. 미리 저장해 둔 완성 쿼리는 쓰지 않고, 계산식·조건 조각을 질문에 맞게 조합해 SQL을 새로 만듭니다.
2. **실행은 하네스를 거쳐서:** 생성된 SQL은 실행 전에 3단계로 검사하고, 읽기 전용 연결에서만 실행합니다. 오류는 고쳐서 다시 시도하되, 위험한 SQL은 고치지 않고 차단합니다.

## 시스템 구조

![시스템 구조](docs/images/architecture.svg)

- **빌드(로컬):** 원천 CSV를 SQLite DB로 만들고(PK·FK 검증, 고객 여정 파생 테이블), 팀 메타데이터 스키마와 시맨틱 정의를 합쳐 브라우저용 데이터 파일로 내보냅니다.
- **실행(브라우저):** 대시보드는 iframe으로 띄우고, 에이전트 엔진은 대시보드가 뜬 뒤 불러옵니다(sql.js → 데이터 → `core.js` → `rag.js` → `agent.js`). 로그는 claude.ai 공유 DB에 저장해 하네스 모니터링 탭에서 봅니다.

### SQL은 누가 만드나

| 실행 위치 | SQL 생성 | API 키 |
|---|---|---|
| claude.ai 아티팩트 | **Claude** — 페이지를 연 사람의 claude.ai 계정으로 호출(아티팩트 `sample` 기능). 첫 호출 때 본인 허용을 받습니다. | 필요 없음 |
| 로컬 · 일반 웹 호스팅 | **템플릿 모드** — LLM 없이, 정의의 계산식·조건 조각에 질문의 그룹·필터를 규칙으로 조립 | 해당 없음 |

- 템플릿 모드는 Claude를 쓸 수 없을 때를 위한 대체 경로입니다. 정의된 지표의 단순 질문은 정확히 답합니다. 하지만 조인·정렬·상위 N·여러 조건이 필요한 질문은 "Claude가 생성해야 하는 질문"이라고 안내합니다.
- Claude 호출이 실패해 대체된 답변에는 이유와 "Claude로 다시 시도" 버튼을 보여 줍니다.
- claude.ai 밖에서도 LLM으로 생성하려면 API 키를 둔 작은 서버(프록시)가 필요합니다. 키를 브라우저 코드에 넣으면 노출되기 때문입니다.

## 질문 처리 흐름

![질문 처리 흐름](docs/images/flow.svg)

| 단계 | 하는 일 |
|---|---|
| 요청 안전성 | 데이터 변경·삭제를 요청하는 질문은 LLM을 부르지 않고 바로 차단합니다. |
| 정의 검색 | BM25(한글 2-gram) + 별칭 일치 점수로 정의를 최대 6개 고르고, 의존 정의·테이블·JOIN 관계를 붙입니다. "20대" 같은 세그먼트는 DB의 실제 코드(`age_band = '20_29'`)로 확인합니다. |
| 데이터 가용성 | 원천 데이터가 없는 지표(예: 캠페인 반응률)는 숫자를 만들지 않고 필요한 데이터를 안내합니다. |
| SQL 생성 | Claude 또는 템플릿 모드. 계산식·조건 조각만 넘기고 완성 SELECT 문은 넘기지 않습니다. |
| 검증 | ① 토큰: 단일 문장, SELECT/WITH만, 위험 키워드·함수, SQLite 방언, 허용 테이블 ② SQLite 컴파일 ③ 실행 계획(바이트코드): 쓰기 연산, 실제로 읽는 테이블·컬럼, JOIN 조건, 타입 비교 |
| 실행 | `PRAGMA query_only` 연결, 최대 5,000행, 8초 제한, 실행 중 데이터 변경 감시 |
| 자동 수정 | 오류 유형(문법·없는 테이블·없는 컬럼·타입·JOIN·함수·시간 초과 등)과 메시지를 수정기에 넘겨 고친 뒤 재검증·재실행(최대 2회). 위험 SQL은 수정하지 않습니다. |
| 로그 | 질문, 검색 순위·Context, 단계별 결과, 시도한 SQL, 수정 이유, 결과 미리보기(식별 키 마스킹)를 Request ID로 저장 |

| 초기 시청 실패 고객 / 푸시 도달 | 4,485명 (36.0%) / 1,655명 |

| VOD · 영화 · LIVE 이용률 | 79.6% · 37.3% · 7.8% |
| 우선 타깃 1위 (이용권 관심 후 미결제) / 푸시 도달 | 18,991명 / 8,152명 (발표 자료 기준) |

"이용권 관심 후 미결제"는 기준이 둘입니다. 발표 자료는 이용권 페이지를 본 미결제 고객 전체(18,991명)를 쓰고, 대시보드 v9 카드는 탐색까지 거친 퍼널 순차 기준(11,568명)을 씁니다. 에이전트는 현재 발표 자료 기준으로 답합니다.

**하네스**

| 입력 | 처리 |
|---|---|
| `DELETE`, `SELECT 1; DROP TABLE …`, CTE 뒤에 숨긴 `INSERT`, `sqlite_master` 접근 | 실행 전 차단 · 수정 시도 없음 · 데이터 변경 0건 |
| 없는 컬럼, `COUNT(` 문법 오류, TEXT 컬럼에 숫자 비교 | 오류 감지 → 자동 수정 → 재실행 성공 |
| `COUNT(DISTINCT …)`, `IN (SELECT …)`, `replace()` 문자열 함수 | 정상 SQL로 통과 (오탐 방지) |
| 데이터 변경·삭제를 요청하는 질문 | LLM 호출 없이 차단 |
| 캠페인 반응률(발송 로그 없음) | 숫자를 만들지 않고 "추가 데이터 필요" |

`npm test`는 위 내용을 포함한 32개 테스트를 LLM 없이 실행합니다. 시맨틱 정의 63개의 SQL 조각이 모두 실제 DB에서 컴파일되는지, LLM에 넘기는 Context에 완성 SELECT 문이 없는지도 확인합니다.

## 실행

Node.js 22.5 이상이 필요합니다(`node:sqlite`). 외부 npm 패키지는 쓰지 않습니다.

먼저 저장소에 없는 입력 두 가지를 넣습니다. 둘 다 고객 단위 데이터라 git에서 제외했습니다.
- `data/csv/`: 원천 CSV 7종 (`user_dim`, `payment_fact`, `behavior_fact`, `watch_daily_fact`, `user_content_summary`, `content_dim`, `content_genre_bridge`)
- `web/dashboard.html`: 팀 대시보드 HTML. 없으면 에이전트 패널만 동작합니다.

```bash
npm run build:db      # data/csv → .build/ott.db
npm run build:data    # .build/ott.db → dist/data/*.js
npm run build         # dist/ 조립
npm run serve         # http://localhost:8765/local.html (템플릿 모드)
npm test              # 회귀 테스트 32개
```

**claude.ai 아티팩트로 배포**
- `dist/index.html`을 페이지로 게시하고, 나머지 `dist/` 파일(`js/`, `vendor/`, `data/`, `dashboard.html`)을 같은 경로로 함께 게시합니다.
- `sample`(Claude 호출), `db`(공유 로그), `downloads`(로그·테스트 결과 저장) 기능을 선언합니다.
- 아티팩트는 외부 CDN에서 스크립트 외 파일을 막으므로 sql.js의 `.wasm`도 같이 게시합니다. WebAssembly가 막힌 환경에서는 `sql-asm.js`로 자동 대체합니다.

## 데이터와 개인정보

- **저장소에서 제외한 것:** 원천 CSV, 생성된 DB와 `dist/`, 팀 대시보드 HTML(고객 키 내장)은 모두 고객 단위 데이터라 저장소에 올리지 않습니다. README 캡처에는 집계 수치만 나옵니다.
- **원천 데이터:** 해커톤 주최 측이 제공한 가명 처리 데이터입니다. 날짜는 365일 이동돼 있고, 고객 키는 64자 해시입니다.
- **로그:** 결과 미리보기에서 `user_key`·`payment_key` 값을 마스킹합니다. 공유 로그는 아티팩트에 접근 권한이 있는 사람이 볼 수 있습니다.
- **Claude 사용량:** 아티팩트에서 Claude 호출은 질문한 사람 본인의 claude.ai 사용량으로 처리됩니다.

## 한계와 다음 단계

- **Claude 호출:** claude.ai에서 `upstream_error`로 간헐적으로 실패합니다. 실패하면 템플릿 모드로 대체하고, 패널의 "Claude 연결 확인"으로 어느 단계에서 실패하는지 가릴 수 있습니다.
- **세그먼트 인식:** 검색된 차원 정의 안에서만 세그먼트 값을 확인합니다. 그래서 "20대 iOS"처럼 차원이 둘인 질문에서 하나가 빠질 수 있습니다. 모든 차원의 값 목록과 대조하도록 개선할 예정입니다.
- **후속 질문:** 이전 대화를 이어받지 않아 "그럼 30대는?"을 독립 질문으로 처리합니다.
- **기준이 여러 개인 지표:** "지속 시청 고객"(5,088 · 5,967 · 4,009명)이나 "이용권 관심 후 미결제"(18,991 · 11,568명)처럼 기준이 여럿인 지표는 하나를 골라 답하고, 다른 기준은 주의 문구로만 알립니다.
- **쿼리 중단 불가:** SQL은 화면과 같은 스레드에서 실행됩니다. 첫 행이 나오기 전에 오래 걸리는 쿼리는 중간에 멈출 수 없어, Web Worker로 옮기는 것이 다음 과제입니다.
- **팀 원본 정의 문서 누락:** 팀 원본 시맨틱 레이어의 정의 13개에 설명·기간·단위 등 문서 필드가 비어 있습니다(`tests/agent.test.cjs`의 `KNOWN_DOC_GAPS`).
- **행동 로그 미적재:** 행동 로그(`behavior_fact`, 45만 행)는 브라우저에 올리지 않습니다. 행동 지표는 고객 여정 테이블의 파생 컬럼으로만 답합니다.
